# 小米 TTS 缺少凭证：配置与修复说明

日志 `缺少小米凭证` 表示配音进程中的 MI_TTS_API_KEY 没有值。它发生在实际网络请求之前，不是 Windows 不支持运行的证据。前面的 scene / cover 日志表示场景数据构建成功，不等于最终有声视频已经完成。

本次检查还确认一处代码遗漏：原 TTS 脚本查找任务快照内的 engine/.env，而密钥通常放在应用项目根目录。如果启动进程没有继承该密钥，就会读不到。新版在隔离渲染器启动时显式读取原项目根目录的 .env，再通过内存环境传递给子进程，不把 .env 复制到任务快照。

## 安装补丁

1. 退出本地应用。
2. 将补丁内 scripts、actions、engine 文件夹中的代码复制到原工程同一路径覆盖。此补丁包含先前的 Windows junction / 取消任务修复，scripts/render-process.cjs 是必需文件。
3. 保留自己的项目 data 与原 .env 配置。
4. 按下面说明补齐小米 TTS 配置，重新运行 start.cmd，再点击“一键出片”。

## 配置位置与内容

在 **与 package.json、start.cmd 同级** 的 `.env` 中添加或修改：

```dotenv
MI_TTS_API_KEY=填写与你的服务地址匹配的有效小米TTS密钥
MI_TTS_BASE_URL=https://api.xiaomimimo.com/v1
```

按实际服务商提供的地址和凭证填写；上面的密钥文字是占位说明。文件名必须是 `.env`，注意 Windows 隐藏扩展名导致的 `.env.txt`。

已有 .env 时请编辑其中相应变量，保留其他设置。不要将凭证放到 data/jobs 的临时 engine 目录，也不要依赖在聊天中曾提供的密钥自动安装到本机。

“设置 → 模型”中的 API Key 用于聊天 / 写稿，自定义文本模型配置不会自动作为 MI_TTS_API_KEY 供配音使用。若暂不使用小米，在“配音”中选择 Edge TTS，保存后重新出片；Edge 需要网络和已安装的 edge-tts。

环境变量中已有的值优先于 .env。修改持久配置后请重启应用；若启动终端设置了旧值，也需要同步修改对应环境变量。

原错误文案中的 token-plan / tp- 是原引擎的特定服务说明。代码并没有据此校验所有密钥前缀；此版本已改为提示“服务地址与有效 TTS 密钥匹配”，避免混淆不同接口的凭证。

## 本次验证

- 10 项文件 / 进程 / 配置测试通过，包含项目根目录 `.env` 读取、从任务工作目录读取根配置、环境变量优先、没有 .env 时的继承模式及文件读取失败提示。
- 本地模拟 MiMo 接口收到正确鉴权、模型 ID、音色和 assistant 角色旁白；配音适配器、动画、合成与封面流程完成，视频可以完整解码。
- 测试音频是合成正弦测试音，**不是真实语音**，没有调用真实小米服务或使用付费密钥。此测试验证程序接线与文件配置，不能验证服务商账户权限、额度、真实音色质量或可用性。
- 任务目录扫描未发现 `.env` 或测试明文密钥。测试密钥只存在于隔离测试目录和进程内存，源码包不包含用户密钥。
- 执行环境为 Linux。Windows / macOS 真机完整媒体链路仍需在相应系统上验证。

细节见 `mimo-config-regression.json`。如果不再报缺少凭证而开始返回 HTTP 401 / 403 等，说明已进入服务调用阶段，应核对对应服务的地址、Key、权限和额度。
