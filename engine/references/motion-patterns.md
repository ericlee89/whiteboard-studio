# 动效卡：纸面动画的词汇与参数纪律

> 来源：`video-shotcraft`（Apache 2.0）的镜头配方卡 `references/shots/`（124 张）。
> 本文件只借它的**结构**（参数表 + 调节手感 + 已知坑）与**手法**，不引入 Remotion，
> 也不复制任何原始素材。原库的动效研究自公开发布的商业宣传片，全部为独立重写、
> 去品牌化；我们同样只取手法，不照抄具体表达。
>
> 原库定位是深色电影感产品宣传片，纸面白板是另一套审美。**最大的换算只有一条：
> 把"发光"换成"落墨"。** 深底上的白热字、辉光、冲击环、光晕，在米白纸面上
> 一律换成墨色加深、压印、纸面凹陷。凡是需要"亮起来"才能成立的卡，这里都剔除了。

## 本文怎么用

1. 写场景前先扫一遍下面的卡，确定这一屏要不要动效、要哪一种。
2. 每屏**最多一个**强调动效。纸面片子的质感来自克制，来自"笔在写"这件事本身。
3. 参数表里的「调节手感」是**判据**，不是建议。越界之后观众会读成什么，都写在那里。
4. 表格里的 `f` 是按 30fps 计的帧数；`beat` 指 `scenes.js` 里 `s.nextBeat()` 切出的一段。

## 现有原语（`lib/render.html`）

渲染器已经是逐帧时间轴（`window.seek(t)`），每个元素有自然时长，笔尖有抬笔间隙。
目前能用的只有三种入场，所有动效都由这三种组合出来：

| 原语 | 行为 | 自然时长 |
|---|---|---|
| 描线 | rough.js 路径按 `stroke-dashoffset` 顺序长出来，A/B 双层做手绘重线 | 线按长度 |
| 填充 | `fill` 型：不透明度 0→1 线性；`fade` 型：`f*1.5` 更快起 | 固定 |
| 逐字 | 文字按字符逐个出现 | 每字 0.06–0.2s |

**基础三原语之上，已有 `motion` 字段**（2026-10-28 加入，见下节）。加了 `motion` 的元素
**不走笔描**，笔会跳过它继续走——这是「元素自己动」与「笔画出一切」的分界，用之前先想清楚。

## `motion` 字段（已可用）

任何元素都能加 `motion: 'blur' | 'scale' | 'slide'`：

```js
s.text(CX, 355, '模型已经定型', { size: 108, align: 'center', motion: 'blur' })
s.rect(240, 300, 1440, 420, { round: true, fill: C.fYellow, fillStyle: 'solid', motion: 'scale' })
s.image(CX, 300, 'sticker', { h: 370, align: 'center', motion: 'slide' })
```

| 值 | 效果 | 典型用在 |
|---|---|---|
| `blur` | 14px 模糊 → 清晰，同时淡入 | 主标题、需要"显影"感的段落 |
| `scale` | 1.6× → 1×（easeOutCubic，收尾自然略过冲） | 卡片、数字、贴纸；`brace-expand` / `outline-word-fill` 都靠它 |
| `slide` | 下移 52px → 归位，同时淡入 | 逐条清单、连续出现的正文行 |

**关键约束（踩过的坑）**
- 带 `motion` 的元素会**摘掉 clip 遮罩**。因为给含 `clip-path` 的 `<g>` 加 transform 时，
  Chromium 会把裁剪一起变换，实测内容被整块裁没。所以动效元素只能靠 opacity/transform 入场，
  不可能"边擦边动"。两者选一个。
- 缩放用 **SVG `transform` 属性**、绕元素中心显式计算（`translate(cx,cy) scale(k) translate(-cx,-cy)`）。
  `CSS transform-box: fill-box` 在这套结构上不可靠，会让元素消失。
- 时长跟随元素自然时长（文字按字数、图形按路径长度），**不可单独指定**。想更短就往
  `config.json` 的 `render.pen` 调，或把元素拆小。
- 入场前约 0.3s 几乎是全透明的，看起来像"慢半拍"。需要更快的话改 `applyMotion` 里的
  透明度系数（现在 `e*1.9`）。
- **一屏最多一个** 动效元素组。全屏都加 motion，就彻底没有手绘感了。
- 回归安全性：`motion` 为 null 时逐帧输出与旧版**完全一致**（已用 10 个时间点逐帧 md5 验证）。

## A 级：现在就能做

### A1. 马克笔下划线 `marker-underline-title`

- **一句话**：标题落定后，关键词下方一笔马克笔下划线从左到右描出来。
- **适用**：标题里强调单个关键词；章节页点睛。
- **落位**：版式 A（开场大标题）、版式 H（总结页）。
- **实现**：不用新原语——`s.squiggle()` 本身就是描线，天生就是这支笔。
  差别在**他现在的 squiggle 是装饰，这张卡要求它当强调**。

| 参数 | 典型值（1920×1080） | 调节手感 |
|---|---|---|
| 描画时长 | 0.33–0.4s（10–12f） | **>0.47s 读作进度条；<0.2s 看不见笔迹方向。** 这是全卡命门 |
| 起笔时机 | 标题完全落定后 +0.13~0.27s（4–8f） | 与标题同动就抢戏——下划线是"看完标题后的强调" |
| 贴字距离 | 字底下方 ≈0.1em（1080p 约 −40 → −20） | 离远读作分隔线；压到字底降部又乱 |
| 倾斜 | 正体字：水平微抖；斜体字：左低右高微上斜 | **斜向画反（左高右低）一眼假**——原库 v1 就是被这个判例抓出来返工的 |
| 线宽 | 中段粗、首尾略细（≈0.6×） | 等宽读作机器线；差异 >2× 读作书法 |
| 覆盖范围 | 只盖关键词，两端各留 6–10px 余量 | 盖住整个标题读作装饰条，强调语义全丢 |

**已知坑**
- 一个场景**只用一次**。标两个词等于没标。
- 纸色为纯白时马克笔色要用 `C.brand` 加深一档，否则浅黄/浅绿在高亮纸上发虚。
- 他封面已有 `coverLayout` 的马克笔高亮；视频内再用同一支笔会呼应，但**不要在同一帧同时出现**（封面与正片不共存，这里只是提醒别在正片首帧做封面式高亮）。

### A2. 花括号揭示 `brace-expand`

- **一句话**：一对小花括号先在中间出现，向两侧弹开并放大，文字被"括出来"。
- **适用**：技术/系统类章节开场；需要"一个符号完成揭示"的极简一拍。
- **落位**：版式 A 的变体，替代「大标题直接写出来」。
- **实现**：描线（括号） + 逐字（文字） + `fill`（文字渐显）。弹开用缩放，**需加 scale 原语**；
  只用现有原语时退化为「括号描出 → 文字逐字」，也成立，只是少了那口"撑开"的劲。

| 参数 | 典型值（1920×1080） | 调节手感 |
|---|---|---|
| 括号入场 | 0.2s 硬切出现（不用淡入） | 硬切是对的（符号"啪"地在那儿）；改淡入会少掉"先看清括号"那几帧，弹开显得突然 |
| 弹开时长 | 0.47s（14f），带一次过冲 ≈9% | **过冲是全片唯一峰值**；拖到 0.6s 以上读作缓慢滑开，没有"撑"的力道；过冲超过两次读作果冻 |
| 括号半距 | HALF≈540px（中心）、INNER≈48px（到内缘） | 决定标题能多宽：内腔 ≈ 2×(HALF−INNER) ≈ 984px |
| 文字宽度 | 落定后占内腔 85–95% | 比内腔窄太多，括号还没到位字就露全了，幕布感变弱；比内腔宽则两头被裁 |
| 框线粗细 | 4–6px，手绘感 | 细于 3px 在米白纸上几乎看不见；粗于 10px 像中括号表格 |

**已知坑**
- 文字若逐字出现，**必须按内腔宽度预留位置**（用等宽占位），否则字一边长出来一边重排，整体会抖。
- 括号不要做得太像代码，政企题材里 `{}` 容易被读成"技术黑话"。稳妥做法：括号里放系统名/功能名，让符号当引用号而不是代码。

### A3. 空心词填实 `outline-word-fill`

- **一句话**：空心描边的关键数字/词，收缩落位后**一帧内**填成实心墨色。
- **适用**：单个数字或利益点的重锤一拍（"3 个坑""零填报"）。
- **落位**：版式 F（参数与价格）/ 版式 C 的强化项。
- **实现**：描线（空心轮廓） + `fill` 硬切。**这是他现有原语最匹配的一张卡**——
  `strokeNode` 走描线，`fill` 型走不透明度，两者本来就是分开的两层。

| 参数 | 典型值（1920×1080） | 调节手感 |
|---|---|---|
| 收缩 | 3.2 倍 → 1 倍，0.37s（11f） | 3.2 倍是"从脸前退开"的量；<2 倍读作普通缩放；>0.67s 就成了缓慢 zoom，冲击全失 |
| 字重 | **500**，不要 700+ | 空心字上 700+ 会让细描边包住一大块空白，读作气球字。500 是空心字的甜点 |
| 描边 | 2px 暖灰（≈`#8a7668`） | 细描边是"制图"语汇；>4px 变涂鸦 |
| 填充时机 | **按帧硬切，≤1f** | **这一下是全卡的目的。** 任何慢扫（>3f）都会把钉子降级成美化动画，不如不做 |
| 填充后 hold | ≥1.2s（36f） | <0.67s 观众来不及读旁边的副行与读数 |
| 停顿 | 填充前留 0.13s 静止 | 完全不留，读者看不到"空"这个状态，填充就没有对比 |

**已知坑**
- **不要加辉光**。原卡靠"白热字 + 一闪辉光"成立，纸面不能发光。换算方式：
  填充前把描边提亮一档（暖灰→略暖），填充时直接压到 `C.ink`，靠**明度断层**代替辉光。
- 填充必须比收缩慢半拍——收缩是"到位"，填充是"定住"。同帧完成读作卡顿。
- 一个场景只钉一个词。钉两个，两个都不重。

### A4. 逐词压印上纸 `paper-title-card`

- **一句话**：一句话按词逐个压到纸面上，其中一词标强调。
- **适用**：章节页大标题；一句话结论。
- **落位**：版式 A / H。
- **实现**：纯逐字原语 + 一词一停顿。**零改动，现在就能用，改的只是节奏。**

| 参数 | 典型值 | 调节手感 |
|---|---|---|
| 词间停顿 | 0.1–0.16s | <0.06s 读作整句一次性出现，丢掉"压印"感；>0.3s 读作卡顿或机器故障 |
| 词内字速 | 0.06s/字（现有 `charSeconds` 下限） | 词内要快，词间要停——对比就是节奏本身 |
| 强调词 | 1 个，用 `C.brand` 或加粗，不换字号 | 换字号会让整行重排；强调用颜色/描边 |
| 行距 | 1.45–1.55 倍 | 压印感需要"留白充分"；<1.35 倍读作挤在一起 |

**已知坑**
- 中文按词切分不要靠空格（中文没空格），在旁白里用 `·` 或显式数组分段。
- 每行 ≤8 字，与现有封面规矩一致。

## B 级：还差一步

`blur-slide`（逐词入场）**已经可用**了——直接用 `motion: 'blur'` 逐词加，就是这张卡。剩下的还缺：

| 卡 | 还缺什么 | 值不值得 |
|---|---|---|
| `typewriter-moves` 打字机改口 | 需"逆序擦除"（逐字消失，反向拉 clip）+ 光标三态 | 值得。讲解"纠正误区"时极好用 |
| `scanline-annotate-focus` 扫描线 + 四角取景框 | 需一条匀速扫描线 + 弹簧收拢 + 框角描线（三个新原语，不是一条轨道） | **最值得**。讲系统截图、指认界面元素比红框箭头高一个档。纪律：扫描线**零缓动**，标注必须滞后 5f——先扫到再框住 |
| `print-texture-transitions` 墨渗转场 | 需 SVG mask + `feTurbulence` + `feDisplacementMap` | **审美最贴，工程最贵**。逐帧截图渲染下 feTurbulence 每帧重算，长片会明显拖慢。且原卡自己写了坑：滤镜有亚像素抖动，结尾必须摘掉 mask 否则永不真静止 |

## C 级：不要碰

原库里这些卡很漂亮，但和纸面白板是两套语言。硬套会立刻变成"一眼 AI"：

- `aurora-bloom-bg-flip`（紫橙柔焦 blob）、`glow-flyline-moves`（暗场光斑飞线）——
  科技蓝大屏味，直接在雷区上。
- `fui-hud-moves`（FUI/HUD 准星）、`slam-entrance-moves`（kanada 透视砸入）——
  军事/发布会语言，政企培训片里显得浮夸。
- `card-flip-reveal` / `card-flock-tumble`（3D 翻卡）——纸面上翻 3D 卡，物理说不通。
- `glitch-cycle` / `tear-streak-transitions`（故障撕裂）——与"手绘讲解"的信任感冲突。
- `gradient-word-sweep`（渐变彩光）、`white-flash-logo-simplify-cut`（液态金属）——纯装饰，无信息。
- `mosaic-reframe`、`page-turn-transitions`（对开门）——太戏剧，节奏跟不上讲解旁白。

## 三条通用纪律

这三条比任何单张卡都重要，来自原库反复出现的返工判例：

1. **帧数确定，不要插值**。凡是"逐字出现"类的，用 `floor` 取整，不要缓动。
   缓动打字读作加载动画。
2. **一个场景一个峰值**。原库每张卡的「能量」字段都标了高/中/低，一张片子里
   高能量拍不超过总场景数的 1/5。他现在的问题是所有场景能量相同，节奏平。
3. **参数越界的效果要写下来**。这是本文件最该延续的习惯——不是"推荐 10 帧"，
   而是"14 帧读作进度条"。写清楚越界之后观众读到什么，下次才有判据。
